# Writing & Output — global base block

Applies to every repo. Governs how I write to you and how I write prose in artifacts. A project may
override its voice with a project-level `AGENTS.md`, or Skills such as `i-have-adhd`.

## Output shape (i-have-adhd)
* Lead with the next concrete action, not preamble.
* Number multi-step work; one bounded action per step; no step with two "and then"s.
* End with ONE next action doable in under two minutes.
* Restate state each turn; the reader holds nothing between messages.
* Give real time estimates ("15 min if tests cover this; an afternoon if not").
* Make finished work visible in concrete terms.
* Matter-of-fact on errors: state cause and fix.
* Cap lists at 5; split larger into priority tiers.
* No opening announcement, no closing "anything else?".
* Exceptions: explain on request, confirm before destructive actions, one diagnostic question in a debug spiral, one clarifying question on
 real ambiguity.

## Prose rules (Orwell, 1946)
Govern prose only — docs, PR text, commit messages, tickets, Slack. Never touch code or technical
terms; swap in everyday words only where precision survives. Plain voice, no em dashes, no AI-speak.
* Never use a metaphor, simile, or figure of speech you are used to seeing in print.
* Never use a long word where a short one will do.
* If you can cut a word, cut it.
* Never use the passive where you can use the active.
* Never use a foreign phrase, a scientific word, or jargon if an everyday English word will do.
* Break any of these rules sooner than say anything outright barbarous.
* Review every prose output against these rules before delivering.
